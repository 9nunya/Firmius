Task: implement the next major TUI UX language hunk.

Goal
Shift the TUI from bordered widget sludge to a flat, grouped, reactive operations transcript.

This hunk should make the TUI feel:
- compact
- live
- editorial
- high-density
- theme-aware

Not:
- over-bordered
- repetitive
- tool-centric
- visually bureaucratic

Why this hunk is needed
Current TUI problems:
1. Quick tool calls consume too much vertical space.
   - every read/list/search/glob call gets its own row/block
   - file-read previews waste space by showing top lines the user usually does not care about

2. Agent prose between tool calls is not shown clearly enough in the transcript.
   - the transcript should feel like Codex-style interleaving:
     - agent prose
     - grouped tool activity
     - more prose
     - live process / diff / result

3. Process-style tools are not rich enough.
   - terminal commands and python should show live output
   - preserve terminal ANSI colors when possible
   - they should feel like live panes, not summary blocks

4. The TUI still relies too much on borders.
   - remove FTXUI borders from the affected tool/render surfaces in this hunk
   - use flat background planes, spacing, left accents, chips, and color hierarchy instead

5. Diff previews should always show.
   - no more collapsed diff previews
   - keep syntax highlighting
   - keep accurate line numbers

6. The previous review found two gaps that must also be fixed in this hunk:
   - help overlay claims scroll controls but is not actually keyboard-scrollable
   - collapsed plan lane hides critical failure states like Failed / Blocked / Cancelled

Important design language
This hunk should implement the following UX language:

- agent prose is first-class transcript content
- quick micro-tools are grouped into compact live rows
- heavy tools remain distinct and rich
- flat surfaces instead of bordered boxes
- glint/pulse only for meaningful live states
- errors stay always visible
- plan lane looks tactical, not dull

Core rules

1. Group quick micro-tools
The following tools should aggregate into compact grouped rows when they occur close together in the same assistant turn:
- file reads
- directory listings
- search/find
- glob
- similar light inspection actions

Desired examples:
- `· Read src/compiler/mod.rs, src/compiler/native.rs, src/cli/main.rs`
- `· Listed src/compiler, tests, examples`
- `· Search "NativeCompiler|emit" in src/compiler`

Behavior:
- show one grouped row per compatible tool category within a rolling local cluster
- while preparing: the row should glint/subtly animate
- while calls keep arriving: append newly prepared/executed targets to the same grouped row
- once settled: render as a compact historical row

Important:
- use relative paths where possible
- do NOT dump top-five-line previews for ordinary reads by default
- the default read representation should be compact
- still keep a way to expand to actual contents if that already exists naturally

2. Do NOT group heavy tools
These should remain distinct richer blocks:
- process / terminal commands
- python execution
- subagent summon / wait
- file edits / diffs
- explicit errors

3. Show agent prose between tool calls
Agent content/messages that occur between tools must be rendered directly in the transcript.

This is critical.
The user should see:
- the prose the agent wrote before calling tools
- the prose between clusters of tools
- the prose after tools/results

Do NOT let grouped tool rendering swallow the agent’s actual narrative content.

4. Process and python tools need live output panes
For terminal commands and python:
- show a flat live output pane
- preserve ANSI terminal colors where possible
- show command header line
- stream output live
- show exit status clearly

Do NOT summarize these into a tiny single-line row.

Important:
- python should not appear as a vague “Python exec” block
- it should look like a live executed command/output surface

5. Diffs must always show
Diff previews should always be visible by default.

Requirements:
- no collapse-by-default for diff previews
- preserve syntax highlighting
- preserve add/remove coloring
- preserve accurate old/new line numbers
- render on flat planes, not bordered panels

6. Remove borders from affected surfaces
For the transcript/tool rendering changed in this hunk:
- remove FTXUI borders
- use background planes, spacing, chips, separators, left accents, and color hierarchy instead

Apply this to:
- grouped tool rows
- process/python panes
- diff previews
- error surfaces touched by this work
- plan lane styling touched by this work

Do NOT regress readability.

7. Help overlay must actually scroll
Fix the prior review finding.

Requirements:
- help overlay remains a real modal
- Esc closes it
- keyboard scrolling actually works
  - arrow keys
  - PgUp/PgDn if practical
- long help content must be navigable

8. Collapsed plan lane must surface bad states
Fix the prior review finding.

Collapsed plan summary must visibly surface:
- Failed
- Blocked
- Cancelled

Do not allow a collapsed plan with failed work to look healthy.

9. Color / motion language
Use the existing theme system where possible, but implement this semantic direction:

- info / inspection tools: cool cyan / info accent
- active/current/live: brighter blue or active accent
- verifying/waiting: amber
- success/done: green
- failures/removed/bad states: red-orange
- historical low-signal metadata: dim slate

Motion rules:
- glint for preparing
- subtle pulse for live/running
- settle/fade for completed rows if easy

Do NOT spam animation everywhere.

10. Flat transcript hierarchy
Prioritize this visual hierarchy:
1. agent prose
2. live work
3. errors
4. plan state
5. historical low-signal tool metadata

The screen should feel like one coherent transcript, not stacked widgets.
